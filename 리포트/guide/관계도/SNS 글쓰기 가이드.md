# SNS 글쓰기 가이드

혼자 도트 게임을 만들며 무엇을 해봤고, 왜 그렇게 했고, 지금 어디까지 왔는지 자연스러운 한국어 존댓말로 전합니다. SNS 초안, 채널 소개, 개발 일지, 기술 블로그에 공통으로 적용합니다.

## 말투와 글에서 드러나는 태도

- 작업 대화에서는 원하는 변화부터 짧게 말하는 편입니다. 새 조건은 “그리고”, “앞으로”로 이어 붙이고, “직접 확인”, “실제로 보여주기”처럼 판정 기준을 구체적으로 둡니다.
- 공개 글은 1인칭 경험을 담은 담백한 존댓말이 어울립니다. “정리했습니다”, “다듬고 있습니다”, “계속 고민 중입니다”처럼 작업 상태에 맞는 어미를 씁니다. 주어가 분명하면 “저는”은 생략해도 자연스럽습니다.
- 작업에서 드러나는 성향은 결과를 직접 보고 판단하고, 만족하지 않은 부분도 차분히 공유하는 쪽입니다. “어떤 부분을 더 살펴보고 있는지”를 구체적으로 적으면 솔직함이 살아납니다.
- 첫 문장은 독자가 바로 알아볼 작업이나 장면으로 시작합니다. 짧은 문단에 한 가지씩 남기고, “오늘은”, “이번에는”은 시간이나 순서가 의미 있을 때 씁니다.

## 작업 스타일을 글에 담는 법

- 바뀐 결과를 먼저 보여주고, 작업 전 어떤 문제가 있었는지와 이번에 잡은 기준을 이어 씁니다. 예를 들어 캐릭터 시안이라면 머리 크기와 몸 비율이 방향마다 달라 보였다는 점을 짚고, T포즈와 8방향에 공통으로 쓸 기준을 만들었다고 설명합니다.
- 작업 단계는 구체적인 동사로 표현합니다. 역할을 나눴다, 움직임을 맞췄다, 게임에서 확인했다, 검수에서 걸린 결과를 제작 단계로 돌려보냈다처럼 실제로 한 일을 씁니다.
- 완료한 부분은 “~했습니다”, 지금 진행하는 부분은 “~하고 있습니다”, 다음 작업은 “~해보려고 합니다”로 구분합니다. 시안·프로토타입·현재 플레이 화면은 독자가 구분할 수 있게 설명합니다.
- 첫 인사에서는 만들고 있는 것과 앞으로 공유할 내용을 짧게 소개합니다. 개발 소식에는 본문과 직접 연결되는 실제 화면을 사용합니다. 비공개 작업명과 공개 범위는 해당 프로젝트 지침을 따릅니다.

## 자주 보이는 단어와 공개 글 대체어

채팅 표본에는 “게시”, “앞으로”, “실제”, “진행”, “확인”, “기록”, “보여”가 반복해서 나왔습니다. 공개 글 사례에서는 “기준을 잡다”, “다듬다”, “작업 흐름”, “고민 중입니다”가 자연스럽게 이어졌습니다. 아래 표현은 글의 맥락에 맞춰 골라 씁니다.

| 작업 대화의 표현 | 공개 글에 쓸 수 있는 표현 |
| --- | --- |
| 실제로 확인 | 게임 안에서 움직임을 확인했습니다 · 화면에서 직접 비교해봤습니다 |
| 보여줘 · 같이 올려줘 | 플레이 영상으로 짧게 담았습니다 · 비교 화면도 함께 올립니다 |
| 수정 · 반영 · 적용 | 비율을 다시 맞췄습니다 · 이번 시안에 반영했습니다 · 움직임을 다듬었습니다 |
| 작업 · 진행 중 | 전투 장면을 만들어보고 있습니다 · 캐릭터 제작 흐름을 정리하고 있습니다 |
| 결과 · 완료 | 이번에 바뀐 부분은 ○○입니다 · ○○까지 만들어봤습니다 |
| 정리 · 기록 | 다음 시안에도 쓸 기준을 잡았습니다 · 진행한 내용을 개발 일지에 남겼습니다 |
| 다시 · 아직 | 한 번 더 비교해보고 있습니다 · ○○는 조금 더 살펴보려고 합니다 |
| 앞으로 · 공유 · 게시 | 다음에는 ○○도 보여드리려고 합니다 · 개발 과정을 조금씩 공유해보려고 합니다 |

게임이나 제작에 필요한 용어는 유지합니다. “마네킹”, “T포즈”, “8방향”, “프로토타입”처럼 독자가 결과를 이해하는 데 도움이 되는 말은 그대로 쓰고, “오케스트레이터 에이전트”처럼 생소한 용어는 전체 진행과 결과 인계를 맡는 역할이라는 설명을 곁들입니다.

## 유형별 예시

**첫 소개**

안녕하세요. 혼자 도트 게임을 만들고 있습니다. 전투 장면부터 처음에 만들었던 프로토타입까지, 개발하면서 바뀌는 모습을 조금씩 공유해보려고 합니다.

**짧은 개발 소식**

캐릭터를 어느 방향에서 봐도 비율이 자연스럽게 이어지도록 몸체 기준을 잡고 있습니다. 이번에는 T포즈와 8방향 시안을 나란히 놓고 머리 크기와 몸 비율을 맞춰봤습니다. 다음 시안에도 이 기준을 써보려고 합니다.

**기술 블로그나 긴 개발 일지**

캐릭터 제작을 몸체, 의복, 장비 단계로 나눴습니다. 단계별 결과를 넘기는 흐름은 연결했고, 지금은 검수에서 발견한 문제를 해당 단계로 돌려보내 다시 작업하도록 다듬고 있습니다. 여러 캐릭터를 만들어도 같은 기준을 유지할 수 있는지 계속 비교해보고 있습니다.

## 다음 글에도 적용하는 기준

초안을 쓸 때 이 가이드와 해당 채널의 최근 확정 글을 함께 봅니다. 최근 사용자가 직접 고친 문장이나 승인한 최종 게시문에서 반복되는 선호를 발견하면 기존 항목을 갱신합니다. 같은 뜻의 규칙은 하나로 합치고, 매체나 프로젝트에만 해당하는 취향은 그 범위에서 유지합니다. X에서는 핵심 변화와 현재 상태를 압축하고, Threads·YouTube 커뮤니티에서는 이유나 고민을 한 문단 더 설명할 수 있습니다. 블로그에서는 구현 흐름과 실제 확인 내용을 필요한 만큼 풀어 씁니다.

욕설, 화가 드러나는 문장, 공격적 표현은 분석·인용·예시·업데이트에 사용하지 않습니다. 바로 써야 할 때는 **무엇이 바뀌었는지 → 왜 그렇게 했는지 → 지금 어디까지 왔는지** 순서로 초안을 잡습니다.

## 참고할 게시 기준

공개 범위, 채널 운영, 첨부 기준은 [SNSManager 프로젝트 전용 지침](../../projects/snsmanager/guidelines.html)을 따릅니다. 말투는 사용자가 검토한 최종 게시문을 기준으로 다듬습니다.
