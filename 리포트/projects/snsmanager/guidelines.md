# SNSManager 작업 지침

- 쇼츠 상단은 사용자가 제공한 `assets/shorts/header.png`(원본: 바탕화면 shorts.png)를 기본으로 사용합니다. 이미지를 자르거나 게임 제목·아이콘·개발 일지 패널을 따로 덧붙이지 않습니다. 게임명 비공개 규칙은 유지합니다.
- 상단 이미지는 페이드 없이 영상 전체에 고정합니다. 개발 일지·회차 표기는 넣지 않습니다. 첫 장면의 영상 페이드인은 사용하지 않아 첫 프레임부터 게임 화면이 보이게 합니다. 중간 장면 전환은 게임 화면과 자막에만 적용합니다.
- 쇼츠는 끊김이 보이는 저프레임 GIF·반복 구간을 제외하고 연속된 실제 녹화 구간을 우선 사용합니다. 출력만 30fps로 바꾸어 원본 끊김을 해결했다고 보고하지 않습니다. 자막은 가로 가운데 정렬을 유지하고 좌우 대칭 안전 폭 안에서 크기·줄바꿈을 조절합니다.
- 쇼츠 첫 프레임부터 영상의 내용을 알 수 있는 소개 문구를 약 2초간 표시하고 이후 설명 자막으로 전환합니다. 같은 장면을 썸네일 후보 PNG로 보관하되, 실제 플랫폼의 썸네일 지정과 구분합니다. 첫 프레임의 배우·이펙트 겹침과 깨짐을 확인하고 문제가 보이면 정상 구간으로 시작점을 옮깁니다. 수정본은 버전이 다른 파일명으로 전달하며 같은 링크를 덮어써 재전달하지 않습니다.

## 개발 소식 게시와 보관 · 2026-11-18 확정

- 기본 게시 대상은 YouTube·Threads·X입니다. 제작·초안 요청을 공개 게시 승인으로 간주하지 않습니다. 사용자가 게시를 요청하면 승인된 대상과 자료로 진행하며, 이미 승인된 범위를 다시 확인받지 않습니다. LinkedIn·Reddit 보류는 유지합니다.
- YouTube에는 개발 쇼츠를 올리고, Threads·X에는 같은 최종 MP4를 직접 첨부하는 방식을 기본으로 합니다. 유튜브 링크만 붙이는 홍보글로 대체하지 않으며 사용자가 링크 공유를 지정하면 그 요청을 따릅니다. 본문은 자연스러운 한글 존댓말로 개발 내용과 앞으로 공유할 과정을 짧게 적습니다.
- 채널 첫 소개글은 YouTube 게시물 탭에도 X·Threads의 첫 인사글처럼 올립니다. 쇼츠 링크 홍보가 아니라 혼자 도트 게임을 만들고 있으며 개발 과정을 공유한다는 인사로 작성하고, 경력 문구·내부 게임명은 넣지 않습니다. 전투 화면→이전 Unity 프로토타입→초기 아트 시안 순서의 이미지 3장을 함께 사용하며 과거 자료와 실제 플레이를 구분합니다. 이미지 속 옛 작업명도 확인해 제외하고 원본은 보존합니다. 기존 소개글이 있으면 임의로 중복 게시하지 않습니다.
- 게시 완료는 계정·본문·실제 첨부·고유 URL을 한 번 확인한 뒤 바로 알립니다. 이후 기록·GitHub 저장·중앙 보고 상태는 공개 게시와 구분해 안내하며, 기록 작업 때문에 게시 여부 안내를 늦추지 않습니다.
- 게시한 영상은 비공개 GitHub 저장소의 `archive/youtube/<날짜>-<영상ID>/` 한 폴더에 최종 영상·썸네일 후보·Shotcut 프로젝트·필수 소스·자막·구성 JSON·게시 URL·무결성 목록을 보관합니다. Threads·X 교차 게시 URL도 같은 영상에 연결합니다. 제안 문안과 실제 게시 내용은 구분하고 확인하지 않은 제목·설명·썸네일 선택을 확정 기록하지 않습니다.
- 기존 변경 때문에 기록 자동 동기화가 막히면 `post ... --defer-sync true`로 이번 기록을 저장한 뒤 해당 폴더만 명시적으로 커밋·푸시합니다. 다른 기록·코드·원본을 일괄 스테이징하지 않습니다. 영상 보관용 체크섬은 Git 줄바꿈 정규화 이후에도 일치하도록 저장 파일과 Git blob 기준을 맞춥니다.

근거: 사용자가 첫 쇼츠 제작·수정, YouTube 업로드, Threads·X 영상 직접 게시, 채널 소개글과 이미지 게시, GitHub 보관에 사용한 방식을 향후 지침으로 유지하도록 요청했습니다.

## 게시물 작성과 검수

초안, 예제, 짧은 문안 수정과 공개 문안을 쓰기 전에 중앙 업데이트, [SNS 글쓰기 가이드](../../guide/%EA%B4%80%EA%B3%84%EB%8F%84/SNS%20%EA%B8%80%EC%93%B0%EA%B8%B0%20%EA%B0%80%EC%9D%B4%EB%93%9C.md), 해당 채널에서 사용자가 최근 승인한 글을 읽습니다. 원격 확인에 실패하면 로컬 가이드와 사용자의 최신 지시를 적용하고 원격 상태는 미확인으로 기록합니다.

- 한국어 글은 실제 경험이나 작업을 담은 담백한 1인칭 `~습니다`, `~합니다`체를 기본으로 씁니다. 작업 소재 하나를 고르고 구체적인 변경과 현재 상태를 설명합니다. T포즈와 8방향 작업에서는 표준 표기인 ‘마네킹’을 사용합니다.
- YouTube·Threads·X에는 같은 소재와 첨부를 사용하고 길이와 정보 배치를 채널에 맞춥니다. Threads와 X는 한국어 중심입니다. 영어 병기는 별도로 요청받은 경우에 작성합니다. LinkedIn과 Reddit 운영은 재개 지시까지 보류합니다.
- 게시·예약·초안의 기본 범위는 세 채널입니다. 예약 직전까지 준비하는 요청은 세 채널 모두 최종 제출을 사용자에게 남깁니다. 게시 전 대상 계정, 본문, 첨부 미리보기를 확인합니다.
- 공개용 제목, 본문, 태그, 자막, 이미지, 파일명과 링크에서 내부 게임명을 확인합니다. 공개용 이름이 확정되기 전에는 ‘개발 중인 도트 게임’ 또는 ‘my pixel-art game’을 사용합니다.
- 실제 플레이, 프로토타입과 아트 시안을 구분합니다. 개발 목표, 출시일, 데모, 스토어 링크와 소재 출처는 확인된 범위에서 설명합니다. 원본을 보존한 상태로 첨부용 산출물을 만듭니다.
- 댓글은 구체적인 장점이나 배울 점을 한두 문장으로 씁니다. 이모지와 질문은 생략하며 직접 해보지 않은 일을 경험으로 쓰지 않습니다. Reddit 재개 시 해당 커뮤니티의 현재 규칙과 실제 플레어를 확인합니다. 본인 댓글의 자동 추천은 등록 직후 해당 댓글에서 선택 해제 상태를 확인합니다. 접근 오류가 발생하면 그 댓글의 URL과 미완료 상태를 기록하고 작업을 멈춥니다.

## 운영 기록과 동기화

- 작업 전 `node scripts/sns.mjs start`로 기록을 갱신합니다. 로컬 변경이나 충돌로 멈추면 기존 기록을 보존합니다.
- `node scripts/sns.mjs post`로 플랫폼별 본문, 작성 방식, 실제 첨부와 게시 URL을 기록합니다. 확인된 게시에는 `published`, 초안에는 `draft`, 실제 게시 여부를 확인하지 못한 경우에는 `unverified` 상태를 사용합니다. 실제 팔로우 작업은 `node scripts/sns.mjs follow`로 기록합니다.
- 게시 기록의 `--image`는 이미지와 GIF를 지원합니다. MP4를 사용한 경우 실제 영상 사용 사실과 보관 위치를 기록합니다. 편집 원본과 최종 영상은 비공개 보관 폴더에서 관리합니다.
- 기록 동기화가 실패하면 로컬 기록을 보존하고 원인을 해결한 뒤 `node scripts/sns.mjs sync`로 재시도합니다. 브라우저 작업은 Chrome 직접 연결을 사용하고 연결 오류가 나면 중단합니다.
