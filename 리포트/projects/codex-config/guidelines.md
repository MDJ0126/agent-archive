## 작업 시 참고 사항

- 게시 전 `node 리포트/check-performance.mjs`의 성능 예산을 통과해야 합니다. 빌드 시간·초기 HTML·목록 데이터·초기 행 수·공개 패키지 용량과 증가량을 기록합니다. 기준은 `리포트/performance-budget.json`이며 단순 통과를 실사용 Core Web Vitals 보증으로 해석하지 않습니다.
- 목록은 50개씩 표시하고 검색·집계는 전체 자료를 대상으로 유지합니다. 자료 증가를 전체 DOM 증가로 연결하지 않습니다. 변경된 글의 결과·이미지·GIF·영상은 필요한 해상도와 매체로 최적화하고, 원본과 기존 증거 링크는 보존합니다.
- 공개 파일은 `site-package.mjs`의 링크 의존성으로 선정합니다. 동적 파일 경로를 새로 추가하면 패키지 포함 여부도 확인합니다. 렌더 캐시를 바꿀 때는 파서·렌더러 변경에 따른 무효화를 유지하고 캐시를 정본으로 취급하지 않습니다.
- 큰 GIF·영상의 누적은 게시판 용량 경고와 별도로 아카이브 계층 분리 대상으로 관리합니다. 예산을 조용히 늘리거나 과거 자료를 삭제해 통과시키지 않습니다. 사이트 변경 시 필요한 한 번의 브라우저 측정과 실제 검색·페이지 이동 증거를 남깁니다.

- 다른 작업의 변경이 많은 경우 공개 `main` 기준 작업 트리를 분리하고, 이번 작업의 소스와 보고서 원본만 스테이징합니다.
- 전역 지침 페이지는 저장소의 `AGENTS.md`에서 생성합니다. 푸시 후 Pages 배포 성공과 개별 공개 본문을 각각 확인합니다.
