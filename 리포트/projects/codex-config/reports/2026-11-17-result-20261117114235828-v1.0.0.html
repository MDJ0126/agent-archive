Codex 설정작업 결과

포폴·블로그 기록 무시와 동일한 기기 ID 형식 적용

검증 대기

요청 대상이 Access가 아닌 기존 기록 무시 방식임을 확인하고 동일 site_device_id 저장·판별 형식으로 맞췄습니다. 실제 폰 재접속은 미확인입니다.

2026년 11월 17일 오후 8:42 KSTv1.0.0작업 결과

작업 결과

포폴 원본의 저장 이름·속성과 UUID 판별을 중앙 보고 사이트에 적용했습니다. 기존 별도 저장 이름도 호환하고 성공한 요청에서 원본 형식으로 갱신합니다. 폰 접속 해결 완료는 아닙니다.

변경 내용

적용 내용

기존 포폴 cloudflare-pages/_worker.js의 site_device_id 저장·읽기 방식을 직접 대조했습니다. 같은 이름, 1년 보관, 경로 /, Secure·HttpOnly·SameSite=Lax로 맞췄습니다. 기존 __Host-tracefolio_device 연결도 읽어 PC 연결을 유지합니다. 허용 값 두 개와 미등록 일반 403은 그대로입니다. Cloudflare Access나 WARP 구성은 변경하지 않았습니다.

검증

실제 index.html에서 원본 형식의 iPhone ID 200 및 site_device_id 갱신, 기존 PC 저장 형식 200 및 원본 형식 갱신, 미등록 403 및 등록 정보 미발급을 확인했습니다. 원본 저장 이름 차이가 폰 실패의 원인이라고 확정하지 않습니다. 사용자 실제 폰 재접속은 미확인입니다. node --check와 보고서 빌드를 수행했으며 테스트 모음은 실행하지 않았습니다.

남은 사항

사용자는 포폴·블로그 기록 무시 방식을 요청했다고 확인했습니다. 폰의 실제 일반 주소 재접속 검증은 남아 있습니다. 도메인이 달라 기존 사이트의 저장 정보가 자동 공유되지는 않으며 현재 연결 절차도 유지됩니다. 폰 접속이 해결됐다고 보고하지 않습니다. 일반 검증 지침과 중복되는 내용이므로 지침 변경 없음.
