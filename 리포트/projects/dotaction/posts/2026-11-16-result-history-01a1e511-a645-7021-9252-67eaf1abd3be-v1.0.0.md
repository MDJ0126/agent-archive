## 변경 내용

### 적용 내용

**현재 DotAction에는 GDScript를 유지하는 편을 권합니다.** C#은 복잡한 시스템이나 기존 C# 코드 활용이 필요할 때 이점이 큽니다.

| 항목 | GDScript | C# |
|---|---|---|
| 개발 속도 | Godot 노드·씬 연결이 간결하고 수정이 빠름 | 코드 구조와 빌드 관리가 더 필요 |
| 언어·도구 | 문법이 단순하고 Godot에 밀착 | 강한 타입 시스템, 제네릭, LINQ, 풍부한 IDE 지원 |
| 오류 확인 | 타입 명시를 활용하면 상당 부분 사전 확인 가능 | 컴파일 단계에서 많은 오류 확인 |
| 실행 성능 | 일반적인 게임 로직에 충분 | 반복 계산·대량 데이터 처리에 유리 |
| 코드 규모 | 작은 기능을 빠르게 조합하기 좋음 | 복잡한 도메인·대규모 코드 관리에 유리 |
| 기존 자산 | Godot API를 바로 활용 | 기존 .NET 라이브러리·C# 코드 활용 가능 |

DotAction의 **전투·장비·보스 패턴·UI·데이터 연결**은 GDScript로 충분히 구현할 수 있습니다. 콘텐츠가 많아지는 문제는 언어보다 데이터 분리와 참조 구조의 영향을 더 크게 받습니다. 정적 타입을 적극적으로 쓰면 유지보수도 개선됩니다.

10년차 클라이언트 개발자이신 만큼 C# 자체는 익숙하시겠지만, **현재 코드를 전부 전환할 이득은 작습니다.** 우선 GDScript로 진행하고, 실제 측정에서 병목이 나온 계산 부분이나 C# 라이브러리가 필요한 부분만 C#으로 분리하는 방식이 합리적입니다. 두 언어를 섞을 때는 호출 경계를 명확히 잡는 편이 좋습니다.
